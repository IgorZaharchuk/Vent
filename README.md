Система управления термокамерой и вентиляцией (v2.0)
 Протестировано на:  ZMod, Klipper v0.13+, FlashForge Adventurer 5M/Pro  
 Архитектура:  Гибридная (Klipper Macros + Python Physics Engine)

   📖 Описание
Это продвинутая программная реализация активной термокамеры без отдельного нагревателя. В качестве источника тепла используется нагревательный стол принтера.  
Ключевое отличие версии 2.0 — внедрение  внешнего вычислительного ядра (`vent_calc.py`) , которое работает в реальном времени, применяя:
1.   Физическую модель Ньютона-Рихмана  (экспоненциальный закон охлаждения/нагрева) для точного прогноза времени до цели.
2.   Фильтр Калмана  для оценки реальной скорости нагрева и отсеивания шумов датчика.
3.   Машинное обучение (On-device):  Система накапливает историю сессий в файле `vent_knowledge.json`, автоматически уточняя коэффициент теплопередачи (`k_heat`) и скорость прогрева стола под конкретные условия помещения.
4.   Адаптивное управление:  Скрипт динамически корректирует температуру стола в процессе нагрева, если прогноз показывает отставание или опережение графика.

   ⚙️ Аппаратная часть
- Воздуховод — специальная конструкция для Adventurer 5M/5M Pro:
https://www.printables.com/model/910736-ventiliatsionnyi-kanal-dlia-adventurer-5m5m-pro
→ Поддерживает два вентилятора: один для внутренней циркуляции, второй — для внешнего охлаждения.
- Сервопривод — управляет заслонкой, переключая между режимами циркуляции и вентиляции.
- Датчик температуры — MAX6675 (термопара K-типа) для точного измерения температуры в камере.
- Циркуляционный вентилятор (5015, 24 В) — подключён к разъёму PLA fan (в printer.base.cfg пин chamber fan переназначен на свободный GPIO во избежание конфликтов).
- Внешний вентилятор — подключён через MOSFET-модуль D4184 для коммутации мощной нагрузки. Для улучшения охлаждения камеры при перегреве вентилятор перевернут, он нагнетает холодный воздух снаружи корпуса в низ камеры.
- Серво — подключён в родной разъём на плате, но требуется установка перемычки для подачи +5 В.

   🚀 Режимы работы

   1. VENT_AUTO (Умный автоматический режим)
Основной режим для прогрева перед печатью или сушки филамента.
```gcode
VENT_AUTO TEMP=<цель> WAIT=<таймаут_мин> [BED_T=<мин_стол>]
```
 Параметры: 
    `TEMP`: Целевая температура камеры (20–60°C).
    `WAIT`: Максимальное время ожидания в минутах (10–600).
    `BED_T` (опционально): Минимальная температура стола. По умолчанию = `TEMP + 10°C`. Максимум ограничен 120°C.

 Логика работы: 
1.   Инициализация:  Скрипт считывает текущую температуру, загружает исторические данные (`k_heat`) и рассчитывает необходимую температуру стола для достижения цели ровно к середине таймаута (оптимизация энергии).
2.   Пауза печати:  Если печать активна, а камера холодна — система ставит печать на паузу (`PAUSE`).
3.   Нагрев и Адаптация: 
        Включается циркуляция (заслонка закрыта).
        Стол нагревается до расчетного значения.
        Каждые 10 секунд Python-скрипт анализирует темп нагрева. Если камера греется медленнее прогноза, скрипт  автоматически повышает  температуру стола (до 120°C). Если быстрее — снижает для экономии ресурса ТЭНа.
4.   Возобновление:  При достижении цели:
        Экструдер прогревается до 100°C (защита от "extruder too cold").
        Печать автоматически возобновляется (`RESUME`).
5.   Сушка:  Если печать не запущена, система работает как термостат, удерживая температуру.

   2. VENT_INTERNAL (Ручная циркуляция)
Режим быстрой внутренней циркуляции без управления столом со стороны скрипта (стол управляется вручную или G-кодом).
    Заслонка: Закрыта (95°).
    Вентилятор: 100%.
    Идеально для ручного теста системы или быстрого локального прогрева.

   3. VENT_EXTERNAL (Интенсивное охлаждение)
Режим аварийного или пост-печатного охлаждения.
    Заслонка: Открыта (175°).
    Вентиляторы: Внутренний и внешний на 100%.
    Обеспечивает максимальный поток холодного воздуха через камеру.

   4. VENT_OFF (Полный сброс)
Выключает всю систему управления вентиляцией.
    Вентиляторы: 0%.
    Заслонка: Закрыта.
    Управление столом: Передается обратно стандартному контролю Klipper (скрипт перестает менять целевую температуру стола).
    Сброс таймеров и ошибок.

   🧠 Ключевые особенности v2.0

   Физически обоснованный прогноз
В отличие от линейной экстраполяции, система использует формулу:
```
T(t) = T_bed - (T_bed - T_start)   e^(-k   t)
```
Это позволяет точно предсказывать время достижения цели даже при замедлении нагрева в конце цикла, исключая ложные ошибки таймаута.

   Самообучение (База знаний)
Система хранит файл `vent_knowledge.json`, содержащий:
    Историю успешных и неудачных сессий нагрева.
    Вычисленные коэффициенты теплопотерь (`k_heat`) для разных условий.
    Реальные скорости прогрева стола.
При каждом новом запуске скрипт использует накопленный опыт для более точного стартового расчета. После каждой сессии данные обновляются.

   Безопасность и защита
     Проверка достижимости (Error 6):  Перед стартом скрипт рассчитывает равновесную температуру. Если цель физически недостижима даже при максимуме стола (120°C) из-за высоких теплопотерь, старт блокируется.
     Динамический таймаут (Error 5):  Ошибка срабатывает только если  физический прогноз  показывает, что цель не будет достигнута до конца таймаута, с учетом текущего темпа.
     Конфликты исключены:  Скрипт управляет столом только когда печать стоит на паузе или в режиме сушки. Во время активной печати (`state == printing`) управление столом полностью отдается slicer/G-коду.
     Стабилизация:  Адаптация температуры стола начинается только после выхода самого стола на заданный режим (задержка 120 сек), что исключает реакцию на переходные процессы.

   🛠️ Установка и файлы
Система состоит из следующих файлов в директории `/opt/config/mod_data/plugins/vent/`:
1.  `vent.cfg` — Конфигурация макросов Klipper и пинаут.
2.  `vent_calc.py` — Ядро системы (Python 3), выполняющее расчеты.
3.  `vent_wrapper.sh` — Скрипт-обертка для демонизации процесса Python.
4.  `vent_knowledge.json` — База данных (создается автоматически).
5.  `vent_state.json` — Текущее состояние машины (сохраняется между перезагрузками).
6.  `vent_debug.log` — Лог работы физического движка.

 Требования: 
    Python 3 с библиотеками: `numpy`, `requests`.
    Настроенный `gcode_shell_command` в Klipper.

   📝 Примеры использования

 1. Печать ABS/ASA с прогревом камеры до 45°C: 
Добавьте в начало G-кода слайсера:
```gcode
M104 S0 ; Выключить экструдер временно
VENT_OFF ; Сброс предыдущих состояний
VENT_AUTO TEMP=45 WAIT=30 BED_T=80 ; Ждать 30 мин, стол минимум 80°C
; Далее стандартный старт печати...
```

 2. Сушка нейлона при 55°C в течение 4 часов: 
```gcode
VENT_AUTO TEMP=55 WAIT=240
```

 3. Проверка статуса системы: 
Вызовите макрос в консоли или добавьте кнопку в интерфейс:
```gcode
VENT_STATUS
```
 Вывод покажет:  Текущий режим, прогноз времени до цели, реальную скорость нагрева (°C/мин), статус ошибки (если есть) и кто сейчас управляет столом.

 4. Аварийное охлаждение после печати: 
Добавьте в конец G-кода слайсера (после выключения нагревателей):
```gcode
M104 S0
M140 S0
VENT_EXTERNAL ; Максимальный обдув на 10 минут (можно добавить таймер отдельно)
G4 P600000
VENT_OFF
```

   🔍 Диагностика
Если система ведет себя некорректно:
1.  Проверьте `vent_debug.log` — там подробно расписаны расчеты физики, значения `k_heat` и причины изменений температуры стола.
2.  Убедитесь, что процесс `vent_calc.py` запущен (проверьте через `top` или логи shell_command).
3.  Для сброса накопленной статистики удалите файл `vent_knowledge.json` (система создаст новый с начальными параметрами).
```
